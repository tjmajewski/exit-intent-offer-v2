## 1. The open question — answer this first

**Why does this store's every modal arrive with no offer in it?**

Eight candidate causes were traced. Six are ruled out (§0 of the plan doc has
the evidence). **Two remain, and they need production data to separate:**

| Candidate | Signature in the decision log |
|---|---|
| Cold-start coin flip — at aggression 7 the engine withholds a discount 30% of the time while the bandit arms are immature | `still testing` |
| High propensity + cart under $40 routes to `revenue_no_discount` | `chose not to discount` |

The super-admin decision log now prints these reasons per decision
(`offerSuppression`, added today). **Read a dozen entries and count the
proportions.** That single observation decides the next move:

- Mostly `still testing` → the coin flip dominates. Aggression 10 removes it
  outright during cold start (`Math.random() > 1.0` is never true). Consider
  whether the merchant-facing dial should mean "suppression rate" at all.
- Mostly `chose not to discount` → the propensity path dominates, and today's
  extension deploy is already the fix. Watch whether offers start appearing.

Rows minted before today have no suppression record and render as plain
"Reminder only, no discount". Only look at fresh ones.

**Secondary observation, free now:** the propensity deflation shipped today
should move first-session browsers 20-28 points down, back under
`HIGH_INTENT_MIN = 70`. If offers do *not* start appearing, propensity was not
the cause.

## 4. Traps, in addition to plan §8

- **A gene being stored is not a gene being executed.** Read the code that
  consumes an arm's output, not just the code that produces it.
- **`amount: 0` is ambiguous** — four intended paths and four failure paths emit
  the same payload. Always check `offerSuppression` before concluding the AI
  "chose" anything.
- **Aggression is inert on most branches.** It moves the margin-guard taper and
  the discount-arm confidence bar. "Turn the dial up" is not a diagnosis.
- **One paying store.** Every arm is keyed `(shop, segment)` with a 20-50 outcome
  cold start. Nothing converges on this traffic. Pooled priors
  (`cluster-priors.server.js`, `archetype-priors.js`) are worth more than any
  new per-shop arm.
- **Scheduled Fly machines do not update on `fly deploy`.** Run
  `./scripts/ops/cron-machines.sh refresh` after every server deploy, or crons
  silently run old code — one had been stale for two weeks.
- **`vite build` and eslint do not catch scope or logic errors.** Today a fix was
  shipped that threw `ReferenceError` on render, and another was a complete
  no-op (a Prisma `select` added to the wrong function), both after a clean
  build. Build-clean is not evidence.
- **Storage APIs throw.** `sessionStorage`/`localStorage` raise in some privacy
  contexts rather than returning null. Use the `store` helper in the extension.
  An unguarded read at module scope kills the entire script.
